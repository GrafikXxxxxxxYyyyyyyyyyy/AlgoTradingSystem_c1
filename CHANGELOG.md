# Изменения и улучшения проекта AlgoTradingSystem

## 2026-02-15 (сегодня)

### 1. Feature engineering — итеративный workflow
- В **`src/mlcore/feature_engineering.py`** в начале файла описана пошаговая схема:
  - Кандидаты добавляются в `mid_features.py` / `spread_features.py`.
  - Запуск скрипта → таблица корреляций с таргетом.
  - Сильнейшие признаки (по порогу или топ-N) переносятся в `all_features.py`.
  - Очистка mid/spread, новая партия кандидатов, повтор.
- **`all_features.py`** — финальный набор для обучения и трейдинга; mid/spread — песочница для экспериментов.

### 2. Сетка только в миллисекундах
- Убраны **`grid_resolution_sec`** и **`resolution_in_seconds`**.
- Единственный параметр: **`grid_resolution_ms`** (5000 = 5 с, 10000 = 10 с, 100 = 100 мс).
- Изменения в **`src/mlcore/processors.py`** и **`src/mlcore/dataloader.py`**.

### 3. Процессоры — выравнивание индекса по сетке
- **`_round_index_ns_to_grid`** в процессорах округляет границы бинов до **шага сетки** (`rule_ns`), а не до 1 с/1 мс.
- Устранены лишние строки при мерже (метки вида 5.0 и 5.001 с больше не дают разные ключи).
- **RawTradesProcessor**: после `resample` индекс тоже выравнивается по сетке и при необходимости дедуплицируется.

### 4. Регулярная сетка после мержа
- В **dataloader** после объединения потоков результат приводится к **регулярной сетке** (`_reindex_to_regular_grid`).
- Шаг строго по `rule_ns` (50 мс, 5000 мс и т.д.) — нет чередования 50/100 мс в выводе.

### 5. Обработка по файлам без лишнего перечитывания
- В **`process_raw_stream`** при заданной сетке каждый файл обрабатывается с **минимальным перекрытием**:
  - tail предыдущего файла + текущий файл + head следующего.
- В процессор передаётся **`keep_ts_range=(t_lo, t_hi)`** — остаются только строки, принадлежащие текущему файлу.
- Данные на стыках не теряются, каждый сырой файл читается один раз.

### 6. Кэш и инкрементальная подгрузка в get_processed_data
- В **`save_dir`** сохраняются **`merged.parquet`** и **`processed_meta.json`** (symbol, grid_resolution_ms, список обработанных файлов по потокам).
- При повторном вызове **`get_processed_data(source="raw", ...)`**:
  - если список файлов совпадает с кэшем — возвращается **только** `merged.parquet` (без перечитывания сырых parquet);
  - если появились новые файлы — обрабатываются только **последний уже обработанный + новые** по каждому потоку, результат склеивается с кэшем (`concat` → `drop_duplicates(keep="last")` → `ffill` → `_reindex_to_regular_grid`).
- Ни один кусок данных не теряется и не дублируется некорректно.

### 7. Скрипт загрузки данных
- **`scripts/download_btcusdc.sh`**: путь сохранения данных привязан к **корню проекта** (родитель каталога `scripts/` → `project_root/data/data_BTCUSDC/`), а не к жёстко заданной папке другого проекта.

### 8. Удалённое и прочее
- Удалены устаревшие ноутбуки и файлы: `feature_engineering_mid_model.ipynb`, `feature_engineering_spread_model.ipynb`, `nn_features.py`, `AUDIT_REPORT_RU.md`.
- Добавлен скрипт **`src/mlcore/feature_engineering.py`** для расчёта корреляций признаков с таргетом (mid/spread) и отбора по порогу или топ-N.
